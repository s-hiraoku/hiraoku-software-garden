# ドキュメント案内

ソフトウェアガーデンの基本方針を定めた正式文書は、[ソフトウェアガーデンの思想](philosophy.md) です。

このリポジトリでは、**最終的なソフトウェアガーデンの設計（`design/`）** と、**現在の進化段階（MVP）の設計・成長プラン（`evolution/`）** を分けて管理します。実装と検証が済んでいない内容を完了扱いにはしません。

## 読む順番

1. [リポジトリ概要](../README.md)。ナーサリーの役割とリポジトリ構成を把握する。
2. [ソフトウェアガーデンの思想](philosophy.md)。仕様、形式検証、結実と収穫、知見還元の基本方針を読む。
3. [用語集（ユビキタス言語）](../GLOSSARY.md)。人とエージェントで意味をそろえるための定義を確認する（外部事例の語彙は [外部参考用語集](references/external-terms.md) にある）。
4. [ソフトウェアガーデン概要設計書](design/overview.md)。最終形における 7 工程の流れ、委譲、結実と収穫、テンプレート方針を確認する。
5. [ソフトウェアガーデン詳細設計書](design/detailed-design.md)。最終形に向けた技術仕様（アーキテクチャ、`.garden/garden.toml` スキーマ、ステートマシン、プロトコル、CLI 仕様）を確認する。
6. [ナーサリーとガーデンの使い方](guides/usage.md)。対象リポジトリへの導入、運用、カタログ管理、ナーサリー自身の開発手順を実行する。
7. [現在の MVP 設計](evolution/current-mvp.md) と [MVP 成長プラン](evolution/roadmap.md)。現在の実装範囲、最終形との差分、今後の段階的な育成計画を確認する。
8. [ソフトウェアファクトリーの参考資料](references/README.md)。背景にある外部の実践事例、公開仕様、検証と出荷の手法、講演資料を参照する。

## 資料の置き場

| 場所 | 内容 |
| --- | --- |
| `philosophy.md` | 思想・基本方針（最上位文書） |
| `design/` | 最終形の設計書（概要設計・詳細設計） |
| `guides/` | 導入・運用・開発の使い方ガイド |
| `evolution/` | 現在の MVP 設計、MVP 成長プラン、実証記録（`evidence/`） |
| `specs/` | ナーサリー自身の承認済み仕様（自己ドッグフーディング用） |
| `references/` | 外部の参考資料一覧、横断メモ、事例（`cases/`）、手法（`methods/`）、講演資料（`sources/`）、外部参考用語集 |

外部資料の記述と、ソフトウェアガーデンで採用した仕様を区別します。
